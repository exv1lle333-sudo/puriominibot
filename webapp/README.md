# 🐉 Purio App — мини-приложение (Telegram WebApp)

Игровая надстройка над PurioBot: очки Purio Points, дракон-питомец с уровнями
и скинами, ежедневные задания, серия входов, статистика VPN и мини-казино.
Работает как отдельный процесс поверх той же базы `data/bot.db`, что и сам бот
— ничего в логике бота не меняет, только добавляет новые таблицы.

## Что внутри

- **Главная** — дракончик (уровень/XP), серия входов (растущая награда,
  сбрасывается каждую неделю), сводка по VPN-часам за неделю.
- **Задания** — 6 ежедневных заданий (зайти в приложение, часы в VPN, ставка
  в казино, профиль, приглашение друга) — очки + опыт дракона.
- **VPN** — статус подписки, график часов онлайн за 7 дней, покупка тарифов
  (списание с баланса — так же, как в самом боте), активация промокода.
- **Казино** — "Кости" (roll-under, честный множитель с комиссией 1%) и
  "Слоты" (3 барабана, драконья тема). Ставки — в Purio Points, не в деньгах.
- **Профиль** — баланс, подписка, рефералка, скины дракона, заглушки
  "Purio Shop" и "Обмен на подарки" (помечены "в разработке" — под них уже
  готова база данных и API, осталось наполнить контентом, когда решите).
- Начисление **2 Purio Points за каждый час активной подписки VPN**
  — фоновая задача `webapp/scheduler.py`, крутится прямо в этом процессе.

## Установка

Ничего дополнительно ставить не нужно — `aiohttp` уже тянется как зависимость
`aiogram`. На всякий случай он также прописан в `requirements.txt` отдельно.

```bash
pip install -r requirements.txt
```

## Настройка (.env)

Добавь/проверь в `.env` (рядом с тем, что уже нужно боту):

```
WEBAPP_URL=https://app.твойдомен.ru
WEBAPP_HOST=0.0.0.0
WEBAPP_PORT=8080
WEBAPP_DEV_MODE=false
POINTS_PER_VPN_HOUR=2
```

`WEBAPP_URL` — это то, что должно открываться по HTTPS и вести на этот сервер.
Как только оно заполнено, в главном меню бота (`keyboards.py`) сама появится
кнопка **"🐉 Открыть Purio App"**.

## Запуск

Мини-аппа — **отдельный процесс**, запускается параллельно с ботом:

```bash
# терминал 1
python bot.py

# терминал 2
python -m webapp.server
```

Для продакшена — два systemd-юнита (или два процесса под pm2/supervisor).
Пример unit-файла:

```ini
[Unit]
Description=PurioApp WebApp
After=network.target

[Service]
WorkingDirectory=/root/PurioBot2
EnvironmentFile=/root/PurioBot2/.env
ExecStart=/root/PurioBot2/venv/bin/python -m webapp.server
Restart=always

[Install]
WantedBy=multi-user.target
```

## HTTPS и Telegram

Telegram WebApp **обязательно** требует HTTPS. Сервер `webapp/server.py`
слушает обычный HTTP на `WEBAPP_PORT` — перед ним нужен реверс-прокси
(nginx / caddy) с SSL-сертификатом (Let's Encrypt).

Пример nginx:

```nginx
server {
    listen 443 ssl;
    server_name app.твойдомен.ru;

    ssl_certificate     /etc/letsencrypt/live/app.твойдомен.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.твойдомен.ru/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

После этого:
1. Пропиши `WEBAPP_URL=https://app.твойдомен.ru` в `.env` бота и перезапусти его.
2. (Опционально) В @BotFather → твой бот → **Bot Settings → Menu Button** укажи
   тот же URL — тогда мини-аппа будет открываться и через кнопку рядом со
   строкой ввода, не только из меню бота.

## Локальная отладка без Telegram

Выстави `WEBAPP_DEV_MODE=true` в `.env` — тогда можно открыть
`http://localhost:8080/?dev_user_id=123` в обычном браузере, и мини-аппа
будет работать под тестовым пользователем `123` без реальной подписи
Telegram initData. **На проде обязательно верни `false`.**

## Как это всё устроено (для разработчика)

- `gamedb.py` — все таблицы геймификации (`game_users`, `points_ledger`,
  `user_tasks`, `vpn_usage_log`, `casino_rounds`, `user_skins`) + бизнес-логика
  (очки, XP/уровни, серия входов, задания).
- `casino.py` — чистые функции игр (кости/слоты), без побочных эффектов —
  легко покрыть тестами или поменять таблицу выплат.
- `scheduler.py` — фоновый цикл, раз в 5 минут проверяет всех пользователей
  с активной подпиской и досчитывает очки за прошедшие целые часы.
- `telegram_auth.py` — проверка HMAC-подписи initData по документации
  Telegram (см. функцию `validate_init_data`).
- `server.py` — aiohttp-роуты + отдача статики из `webapp/static/`.
- `static/` — фронтенд на чистом JS без сборки (никакого webpack/npm),
  поэтому открывается мгновенно даже на слабом интернете в мини-аппе.

### Как расширить

- **Наполнить Purio Shop / обмен на подарки**: эндпоинты `/api/shop` и
  `/api/gifts` уже существуют и возвращают `available: false` — когда решите
  их запустить, добавьте туда реальные товары/призы и переключите на `true`.
  Таблица `user_skins` и каталог `DRAGON_SKINS` в `gamedb.py` уже готовы под
  платные скины дракона.
- **Больше заданий**: добавь запись в `TASKS_CATALOG` в `gamedb.py` — фронтенд
  подхватит новое задание автоматически (просто нужно вызывать
  `bump_task_progress(user_id, "код_задания")` в нужном месте кода, когда
  условие выполняется).
- **Реальный трафик в графике VPN**: сейчас `scheduler.py` пытается достать
  реальный трафик пользователя через `remnawave_client`, но названия полей в
  SDK `remnactual` не сверялись (см. комментарий в коде) — при необходимости
  поправь `_try_get_traffic_bytes()` под свою версию панели.
